# TextVault Pro — Recovery Guide (New Windows Machine)

How to fully recover TextVault Pro from GitHub on a fresh Windows server.
This file is factual; anything not determinable from the repository is
marked as such. Last verified on the migration backup of 2026-09-05
(commit `4026844` + the accessibility WIP that follows it).

## 1. Clone

```text
git clone https://github.com/psychogdz/TextVault.git
cd TextVault
```

Authentication uses the normal Git / GitHub CLI credential mechanism only
(`gh auth login` or a stored credential helper). No tokens are stored in
the repository.

## 2. Node.js

Node.js **22.x** was used for all verification on the previous server
(v22.23.2). `package.json` declares no `engines` field, so the exact
minimum must be determined from the repository; Node 22 LTS is the
verified choice. npm 10.x was used.

## 3. Install dependencies

```text
npm ci
```

Note (Electron ≥ 42): the Electron binary is downloaded lazily on first
run rather than during `npm ci`. Any of `npm start`, `npm test`, or
`npm run test:e2e` triggers the download; packaging reads
`node_modules/electron/dist`.

## 4. Tests

```text
node test/syntax.cjs     # renderer module syntax check
npm test                 # unit (71) + IPC/architecture (32)
npm run test:e2e         # full Electron E2E suite (155 checks)
```

The verified baseline at migration time: 19/19, 71/71 + 32/32, 155/155 —
all exit 0 (the E2E includes 8 accessibility-invariant checks added by
the in-progress screen-reader audit WIP).

## 5. Run the app

```text
npm start
```

## 6. Build / package / release

```text
npm run package          # portable build + smoke + zip  (release/, gitignored)
npm run release          # package + Inno Setup installer + install/uninstall verification
node test/make-release.cjs upgrade   # upgrade-over-existing-install verification
```

## 7. Windows installer requirements

- **Inno Setup 6** compiler (`ISCC.exe`). `test/make-release.cjs`
  discovers it in this order: `TEXTVAULT_ISCC` env var →
  `tools/innosetup/ISCC.exe` (gitignored, may be empty) → `PATH` via
  `where ISCC.exe` (covers Chocolatey installs) → standard
  `Program Files (x86)/Inno Setup 6` locations.
- No other external tools are required; the portable build uses the
  PowerShell `Compress-Archive` cmdlet.
- `test/secrets-check.ps1` contains a hardcoded path from the ORIGINAL
  development machine and does not run elsewhere; it is not referenced by
  any npm script (the equivalent scan is documented in SECURITY.md).

## 8. Important folders

```text
electron/   main process (main.js, preload.js, ipc/, services/)
src/        renderer (index.html, quick.html, js/, styles/, assets/)
shared/     ESM modules shared by main + renderer (i18n, validation, …)
test/       syntax/unit/ipc/e2e tests + make-portable/make-release/release scripts
docs/       product/engineering documentation (PROGRESS.md is the state record)
tools/      optional bundled toolchain (gitignored — empty after clone)
```

## 9. Where local runtime data lives

- userData (IndexedDB + settings): `%APPDATA%\TextVault` by default
  (Electron convention), overridable via the `TEXTVAULT_USER_DATA`
  environment variable.
- Exports/backups land wherever the user picks in the native dialogs
  (test mode redirects them to `TEXTVAULT_TEST_DIR`).

## 10. Intentionally NOT in Git

`node_modules/`, `dist/`, `release/`, `test-output/*` (except the README
screenshot `test-output/dashboard.png`), `tools/`, logs, `.env*`, keys.
All are regenerated by the steps above; `release/` artifacts are rebuilt
by `npm run release`.
